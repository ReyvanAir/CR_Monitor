Overview

A classroom that can tell you what it feels like

An ESP32-S3 node measures temperature, humidity, illuminance and sound level in a teaching room, then publishes them as JSON over MQTT every two seconds. A local Docker stack validates, stores and charts the stream. The point is to replace "it feels stuffy in here" with a number somebody can act on.

What it measures

Four quantities, three sensors. Each has a threshold band; leaving the band raises a local alarm on the buzzer and the panel, and flags the reading in the telemetry payload.

QuantitySensorBus / pinUnitsAlarm band
TemperatureSHT3x I²C 0x44°C 18.0 to 30.0
Relative humiditySHT3x I²C 0x44% reported only
IlluminanceBH1750 I²C 0x23lx 300 to 800
Sound levelMAX4466 GPIO5 (ADC1)dB rel. peak ≤ 70

Thresholds are placeholders

The five limits above were chosen to make the alarm path testable, not because a standard says so. Before this collects data anyone will cite, each one needs to be justified against a real source and the value here changed to match.

Data path

Two paths leave the node, and only one of them needs a network. That split is deliberate: a room that is too hot should beep whether or not the school Wi-Fi is up.

Project stages

The build runs in five stages. They are sequential because each one depends on the last producing trustworthy output: there is no point storing readings you have not yet confirmed are real.

  1. Simulation DONE

    Wokwi layout in diagram.json. Sensor logic and thresholds proved out before any hardware was wired, so early bugs were logic bugs rather than soldering bugs.

  2. Real hardware and MQTT DONE

    The physical node: three sensors on real buses, a boot self-test, the TFT dashboard, the buzzer, and JSON telemetry published to a broker. This is what CR_Monitor.ino is.

  3. Storage and dashboard CORE RUNNING

    The Docker stack: Mosquitto, Node-RED, InfluxDB, Grafana. The sensor stream is landing and charting. The second stream planned for this stage, an occupancy bucket entered per lesson, is not wired up yet.

  4. Offline analysis NOT STARTED

    Export the stored series and write it up: conditions against occupancy, time of day and the comfort responses from stage 5.

  5. Human feedback NOT STARTED

    An anonymous form asking how the room actually feels, running beside the sensors rather than through them. Sensor data says the room is 29 °C; only a person can say whether that stopped them concentrating.

Design commitments

Four decisions shape most of the code. They are worth knowing before reading it, because several things that look like omissions are these choices being enforced.

Sound is a level, never a recording

The microphone path computes a decibel figure and throws the samples away. No audio is buffered, stored or transmitted, and there is no code path that could do so. Occupancy, when it arrives, is a bucket (Unoccupied, Low, Medium, High) rather than a headcount. Both choices cost accuracy and are worth it: a monitor that records a classroom is a monitor nobody consents to.

The node stays dumb

Firmware publishes. It does not subscribe, accept commands, or hold configuration that can be changed remotely. Anything clever (unit conversion, range rejection, aggregation, alerting policy) belongs in Node-RED where it can be changed without a reflash and without physical access to a device mounted on a wall.

The local alarm does not depend on the LAN

Threshold evaluation, the buzzer and the panel all run from the sample loop, upstream of any network state. Wi-Fi and MQTT are serviced in the same loop but nothing waits on them. Pull the router out and the node keeps measuring, keeps displaying and keeps beeping.

Alert rules exist twice, on purpose

The node decides when to beep. Node-RED separately decides when to raise a dashboard alert. This is duplication, and the alternative is worse: a single rule in Node-RED means the buzzer stops working the moment the broker does. Keep the two in sync by hand and accept the cost.

Known limits

Things a reader should not assume this system does.

  • The sound figure is relative, not certified. A MAX4466 is an electret capsule and an amplifier with a gain trimpot, not a sound level meter. The number is calibrated at two points and reproducible on this node; it is not dB(A) and should never be reported as such.
  • The broker is open. allow_anonymous true is fine on a bench and wrong anywhere else. Authentication is a prerequisite for real deployment, not a nice-to-have.
  • Humidity has no alarm band. It is measured, published and charted, but nothing raises on it, because no defensible limit was chosen.
  • One node, one room. The topic tree and the MAC-derived node id support many nodes; none of the multi-node behaviour has been exercised.
  • The panel clock is local, the data is UTC. Deliberate, and easy to break. See time handling.
